Кофейный автомат — Coffee Vending Machine Simulator (CVM-2026)
Интерактивный 3D-симулятор кофейного автомата на Unity (C#). Построен по лабораторным работам
№1 («Диаграммы переходов состояний STD») и №2 («Описание программы»).
Версия 1.0 · Windows 10/11 · управление мышью (Esc — отмена покупки).
> **Важно: что проверено, а что нет.** В среде, где создавался проект, не было Unity Editor, поэтому проект
> **не открывался в Unity и Windows-сборка не собиралась**. Проверено следующее: (1) вся бизнес-логика
> (21 автотест) выполнена реальным запуском; (2) весь код C# компилируется против облегчённых заглушек API Unity;
> (3) механизм корутин/твинов проверен на эмуляторе планировщика. **Визуальная часть (вид сцены, плавность анимаций,
> расположение элементов) не наблюдалась** — для неё приложен протокол ручной проверки
> `Docs/Протокол_проверки.md`. Если при первом запуске в Unity что-то выглядит не так — это ожидаемо, смотрите
> раздел «Известные ограничения».

1. Быстрый старт
Установите Unity 2022.3 LTS (проект зафиксирован на 2022.3.62f1; Unity Hub предложит открыть с вашей
установленной 2022.3.x — согласитесь. Unity 6 тоже подойдёт, потребуется «Upgrade»). Конвейер — Built-in (3D Core).
Unity Hub → Add → Add project from disk → выберите папку `CoffeeVendingMachine`.
Дождитесь импорта. Редакторский скрипт `CvmProjectSetup` сам создаст сцену `Assets/_Project/Scenes/Main.unity`
(камера + `GameManager`), добавит её в Build Settings и включит нужные шейдеры в сборку.
Если этого не произошло — меню CVM → Создать сцену Main.
Откройте `Main.unity` и нажмите Play. Больше ничего настраивать в Inspector не нужно: 3D-модель автомата,
интерфейс, звук и все связи создаются кодом при запуске (`GameManager`). Запуск работает даже из пустой сцены.
Сборка для Windows: меню CVM → Собрать Windows-приложение → результат в `Builds/CVM-2026/CVM-2026.exe`
(или стандартно: File → Build Settings → Windows, x86_64 → Build).
Разрешение: от 1280×720; интерфейс масштабируется (CanvasScaler 1920×1080, match 0.5), камера сама подбирает поле
зрения под пропорции окна. На 1280×720 текст на корпусе автомата мелкий — рекомендуется окно от 1600×900.
PIN режима обслуживания по умолчанию: `1234` (меняется в режиме обслуживания → «Состояние» → «Сменить PIN»).
Файл сохранения: `Application.persistentDataPath/cvm_save.json` (меню CVM → Открыть папку сохранений).
Чтобы вернуться к заводским данным — закройте приложение и удалите этот файл.

2. Как пользоваться
Действие	Что происходит
Наведите курсор на карточку напитка	плавная подсветка и увеличение
Клик по карточке	выбор напитка, экран показывает название/цену, справа выезжает панель оплаты
Кнопки 10/50/100/500/1000 ₽	купюра вылетает у кнопки, летит к приёмнику и втягивается; сумма на экране «бежит» вверх
Сумма ≥ цены	автоматическая проверка оплаты → приготовление
«Оплатить»	завершение попытки оплаты: при нехватке — отказ и возврат всех внесённых денег
«Вернуть деньги» (или Esc)	подтверждение → отмена покупки → купюры выезжают в лоток возврата
Переплата	после приготовления — выдача сдачи в лоток
Готовый стакан в отсеке	кликните по стакану, чтобы забрать — продажа фиксируется в журнале
«Обслуживание» (справа вверху)	PIN → режим персонала
«+ / − / Звук»	громкость и отключение звука
Режим обслуживания: Напитки (название, цена, время, включить/отключить, рецептура, добавление),
Ингредиенты (пополнить / установить остаток / минимум; «МАЛО» подсвечивается), Журнал продаж (записи и итоги),
Состояние (текущее состояние FSM, ингредиенты на исходе, смена PIN). Войти можно только в состояниях
«Начальное»/«Ожидание выбора»; если покупка идёт — сначала предлагается отменить её и вернуть деньги.

3. Соответствие ЛР-1 (STD) → реализация
Переход из диаграммы STD	Состояние FSM / метод модели
Начальное → Ожидание выбора (активизируется каждый раз)	`Initial → WaitingForDrink`, `Activate()`
Выбор сделан = НЕТ → Начальное	`WaitingForDrink → Initial` по таймауту бездействия (`idleTimeoutSeconds`, 60 c), `TimeoutNoSelection()`
Выбор сделан = ДА / Запрос оплаты	`WaitingForDrink → WaitingForPayment`, `SelectDrink()`
Сумма достаточна = НЕТ → Отказать в покупке	`WaitingForPayment → CheckingPayment → Refunding → Initial`
Сумма достаточна = ДА → Уведомить и приготовить	`CheckingPayment → PreparingDrink`
+ переплата → Вернуть разницу	`PreparingDrink → ReturningChange → DispensingDrink`
Нажата «Вернуть деньги» → Вернуть деньги	`WaitingForPayment → Refunding → Initial`
Выдать товар → Напиток взят = ДА → Начальное	`DispensingDrink → WaitingForPickup → Initial`
(добавлено) ошибка / обслуживание	`Error → Refunding/Initial`, `AdminMode`
Допустимые переходы заданы одной таблицей в `VendingMachineStateMachine`; недопустимый переход не выполняется.
Принятые технические решения (неоднозначности документации)
Недостаточная сумма. В STD «Отказать в покупке» ведёт сразу в начальное состояние и не говорит о судьбе денег.
По требованию безопасного поведения деньги возвращаются (состояние `Refunding`), покупка пишется в журнал как «Отказ».
Момент «завершения неудачной попытки» — нажатие «Оплатить» (или истечение `paymentTimeoutSeconds`, 90 c).
Порядок «сдача → выдача». Следуя ТЗ: приготовление → сдача → выдача напитка → ожидание, пока напиток возьмут.
Списание ингредиентов — один раз, в момент успешной оплаты (вход в `PreparingDrink`). При ошибке до выдачи
списание откатывается, деньги возвращаются. Двойное списание исключено проверками модели.
Продажа записывается один раз — в момент подтверждения получения напитка (клик по стакану).
Режим обслуживания защищён PIN (в ЛР-2 способ доступа не определён).
Расхождение ЛР-2 и проекта: в ЛР-2 указаны «HTML, CSS, JavaScript, веб-браузер». Данный проект реализован на
Unity/C# по заданию. При сдаче работы раздел «Языки программирования» и «Программное обеспечение» в ЛР-2
нужно привести в соответствие (Unity, C#, Windows-приложение).
Данные вместо кода: меню, цены, рецептуры, остатки, номиналы — в `Assets/_Project/Resources/Config/default_data.json`
(используется при первом запуске или повреждённом сохранении) и далее в `cvm_save.json`. ScriptableObject не
применялись: данные редактируются прямо в приложении и сохраняются в JSON.

4. Архитектура
```
Assets/_Project/
├─ Scripts/                         (сборка CVM.Runtime)
│  ├─ Core/        VendingState, VendingMachineStateMachine (FSM), VendingMachineModel (логика, без Unity),
│  │               SalesJournal, VendingMachineController (оркестратор потоков), GameManager (корень)
│  ├─ Payment/     PaymentController (деньги заказа, разложение сдачи), RefundController (возврат строго один раз)
│  ├─ Preparation/ IngredientInventory (атомарное списание), CupView (3D-стакан)
│  ├─ Data/        DrinkData, IngredientData, RecipeData, SaleRecord, AppSettings, SaveData
│  ├─ Persistence/ SaveLoadService (JSON, атомарная запись, .bak, обработка повреждений)
│  ├─ Audio/       AudioManager (синтез звуков кодом; можно подменить файлами), Snd
│  ├─ Animation/   Tween/Ease/AnimSlot, Routines (безопасный запуск + watchdog), Effects (частицы),
│  │               Machine-/UI-/Money-/Preparation-/DispensingAnimationController
│  ├─ Scene/       MachineBuilder (3D-модель из примитивов), SceneBuilder, MachineRig, MachineLayout, CameraFit, MaterialFactory
│  └─ UI/          MainUIController, DrinkSelectionUI, PaymentUI, MessageUI, AdminUIController, SalesHistoryUI,
│                  UIFactory, HoverEffect, Theme
├─ Editor/         CvmProjectSetup (автосоздание сцены, меню CVM)
├─ Tests/EditMode/ VendingLogicTests (NUnit, Unity Test Runner)
└─ Resources/Config/default_data.json
```
Принципы: логика (`VendingMachineModel`) не знает про Unity и не может быть обойдена интерфейсом; анимации только
отображают состояние; переход FSM к следующему шагу выполняется после завершения соответствующей анимации;
единовременно работает один «поток» операции (`busy`), поэтому повторные нажатия не создают дублей.
Поиск объектов через `Find` в Update не используется; подписки снимаются в `OnDestroy`.
Prefab-файлы не создавались: модель автомата, купюры (пул), стакан и окна строятся процедурно. Сцена `Loading.unity`
не нужна (загрузка мгновенная).

5. Анимации (все связаны с логикой состояний)
Ожидание: «дыхание» свечения экрана, пульсация индикатора и светодиодной полосы, мягкая подсветка карточек, мигающая подсказка.
Выбор: наведение (цвет+масштаб), упругий отклик, акцентная рамка выбранной карточки, остальные приглушаются, экран заказа
с наполняющимся стаканчиком, выезд панели оплаты с поочерёдным «пружинением» кнопок.
Внесение денег: появление купюры у кнопки → полёт по дуге → поворот плашмя → втягивание в щель; вспышка светодиода;
сумма «бежит» вверх; сумма в модели меняется сразу.
Проверка оплаты: спиннер → зелёная вспышка («Оплата принята») или красная тряска («Недостаточно средств»).
Возврат/сдача: купюры выезжают из щели, падают в лоток с отскоком, лежат, затем «забираются»; сумма обнуляется после выдачи.
Приготовление: подсветка окна, стакан выезжает из отсека по дуге и встаёт на лоток, сопло опускается, разгоняются шестерни,
струя (цвет напитка), уровень жидкости и пена, пар, прогресс и оставшееся время, финальная вспышка и звонок.
Выдача: лоток опускает стакан, открывается дверца, стакан пульсирует ореолом; по клику стакан вылетает к зрителю с искрами,
дверца закрывается, лоток возвращается.
Ошибки/отмены: красное мигание индикатора и полосы, тряска дисплея, тосты, тряска карточки/окна PIN.
Интерфейс: тосты, модальные окна (затемнение + «упругое» появление), окно PIN, панель обслуживания, переключение вкладок.

6. Тестирование
Автотесты логики (`Assets/_Project/Tests/EditMode/VendingLogicTests.cs`): запускаются в Unity
(Window → General → Test Runner → EditMode) и вне Unity: `cd Tools/LogicTests && dotnet run` — 21 тест, все пройдены
(сценарии 1–6, 7–8, 9 на уровне данных, 10, а также ошибки, откат ингредиентов, таймаут, лимит внесения, разложение сдачи).
Сценарий 9 «перезапуск»: проверена круговая передача `SaveData` через модель; чтение/запись самого JSON-файла на диске
в Unity не запускались.
Остальное — по `Docs/Протокол_проверки.md` (ручная проверка в Unity, в т.ч. визуальная).
7. Заменяемые ресурсы
Вся графика — процедурная (примитивы, материалы, спрайты). Звуки синтезируются; чтобы подставить свои, положите файлы
`Click.wav`, `Select.wav`, `Insert.wav`, `Accept.wav`, `PaymentOk.wav`, `Refuse.wav`, `Refund.wav`, `Change.wav`, `PrepStart.wav`,
`Mechanism.wav`, `Pour.wav`, `Ready.wav`, `Dispense.wav`, `Take.wav`, `PanelOpen.wav`, `PanelClose.wav`, `Error.wav`, `Hover.wav`
в `Assets/_Project/Resources/Audio/SFX/` — они автоматически заменят синтез. Можно улучшить: 3D-модель корпуса, стакан
(сейчас цилиндр), текстуры, звуки.
8. Известные ограничения
Не проверено в Unity Editor и не собиралось (см. начало).
Кнопок номиналов на панели — до 5 (первые 5 из `denominations`).
Шрифт — системный Segoe UI (кириллица и «₽»); на Windows доступен всегда.
Параметры времени (`idleTimeoutSeconds`, `paymentTimeoutSeconds`, номиналы) правятся в `default_data.json` до первого запуска или в `cvm_save.json`.
Конвейер Built-in; для URP потребуется конвертировать материалы (код материалов совместим с URP Lit/Unlit, но не проверялся).
