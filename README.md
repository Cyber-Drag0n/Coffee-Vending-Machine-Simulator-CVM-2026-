# Coffee Vending Machine Simulator (CVM-2026)

Интерактивный 3D-симулятор кофейного автомата, разработанный на **Unity и C#**. Пользователь выбирает напиток, вносит виртуальные деньги, наблюдает за приготовлением и забирает готовый стакан. В приложении также есть режим обслуживания, учёт ингредиентов и журнал продаж.

Проект демонстрирует реализацию бизнес-процесса через **конечный автомат состояний (FSM)**, разделение бизнес-логики и визуального слоя, обработку оплаты и возвратов, сохранение данных в JSON и автоматизированное тестирование.

## Возможности

- **Интерактивный 3D-автомат.** Корпус, элементы интерфейса и многие объекты сцены создаются программно при запуске — отдельные prefab-файлы не требуются.
- **Выбор напитка.** Карточки напитков, цена, рецепт, время приготовления и доступность с учётом остатков ингредиентов.
- **Имитация оплаты.** Приём виртуальных купюр номиналом 10, 50, 100, 500 и 1000 ₽, проверка достаточности суммы и ограничение общей внесённой суммы.
- **Возврат денег и сдача.** Отмена заказа, возврат при недостаточной оплате или ошибке, выдача сдачи при переплате.
- **Анимации процесса.** Движение купюр, работа механизмов, приготовление напитка, появление пены и пара, выдача и получение стакана.
- **Режим обслуживания.** Управление меню и ценами, доступностью напитков, рецептурами и запасами ингредиентов.
- **Журнал продаж.** Запись результатов операций, сумм оплаты и сдачи, просмотр истории и итогов.
- **Сохранение состояния.** Меню, настройки, остатки и журнал сохраняются между запусками в JSON-файл; при повреждении сохранения предусмотрена попытка восстановления из резервной копии.
- **Звуковое сопровождение.** Звуковые эффекты генерируются программно; их можно заменить собственными WAV-файлами.
- **Автотесты бизнес-логики.** Тестирование модели, переходов состояний, оплаты, возврата и расхода ингредиентов без необходимости запускать визуальную сцену.

## Запуск в Unity

1. Скачайте или клонируйте репозиторий и распакуйте проект, если он загружен архивом.
2. В Unity Hub выберите **Add → Add project from disk** и укажите папку `CoffeeVendingMachine`.
3. Дождитесь окончания импорта. При первом открытии редакторский скрипт `CvmProjectSetup` должен создать сцену `Assets/_Project/Scenes/Main.unity`, настроить её для сборки и добавить необходимые шейдеры.
4. Откройте сцену `Main.unity` и нажмите **Play**.

Если сцена автоматически не появилась, используйте меню Unity **CVM → Создать сцену Main**. Основная сцена, 3D-модель автомата, UI и связи компонентов формируются программно.

Рекомендуемое разрешение окна — **1600 × 900** или выше; минимальное ориентировочное разрешение — **1280 × 720**.

## Управление

| Действие | Результат |
|---|---|
| Навести курсор на карточку напитка | Подсветить и выделить карточку |
| Нажать на карточку | Выбрать напиток и открыть панель оплаты |
| Нажать кнопку номинала | Внести виртуальную купюру |
| Нажать «Оплатить» | Проверить внесённую сумму; при недостатке денег покупка отклоняется и средства возвращаются |
| Нажать «Вернуть деньги» или `Esc` | Запросить отмену покупки и возврат внесённых средств |
| Нажать на готовый стакан | Забрать напиток и завершить продажу |
| Нажать «Обслуживание» | Открыть ввод PIN и перейти в панель персонала |
| Использовать кнопки громкости и звука | Изменить громкость или отключить звук |

Состав и расход ингредиентов задаются рецептурой каждого напитка в конфигурации. Напиток становится недоступен, если он отключён, для него не задан рецепт или не хватает нужных ингредиентов.

## Режим обслуживания

PIN по умолчанию — **`1234`**. Его можно изменить в панели обслуживания на вкладке «Состояние».

Доступны следующие разделы:

- **Напитки:** редактирование названия, цены, времени приготовления, статуса доступности и рецептуры; добавление напитков.
- **Ингредиенты:** просмотр остатков, пополнение запасов, установка количества и минимального порога. Низкий остаток подсвечивается.
- **Журнал продаж:** просмотр записей и финансовых итогов.
- **Состояние:** текущее состояние FSM, сведения об ингредиентах и смена PIN.

Режим обслуживания не должен вмешиваться в незавершённую покупку: сначала требуется закончить или отменить её.

## Как устроен проект

Основной код находится в `Assets/_Project/Scripts/`.

```text
Assets/_Project/
├── Editor/
│   └── CvmProjectSetup.cs       # Автосоздание сцены и команды меню CVM
├── Resources/
│   └── Config/default_data.json # Начальные настройки, меню и запасы
├── Scripts/
│   ├── Core/                    # FSM, модель автомата, журнал, контроллеры
│   ├── Payment/                 # Оплата, расчёт сдачи и возвраты
│   ├── Preparation/             # Инвентарь и представление стакана
│   ├── Data/                    # Модели данных и настройки
│   ├── Persistence/             # Загрузка и сохранение JSON
│   ├── Audio/                   # Звуковые эффекты
│   ├── Animation/               # Анимации автомата, денег, напитка и UI
│   ├── Scene/                   # Программное построение сцены и модели автомата
│   └── UI/                      # Интерфейс покупателя и персонала
└── Tests/EditMode/              # Тесты логики для Unity Test Runner

Tools/LogicTests/                # Консольный запуск тестов без Unity Editor
```

### Архитектурные решения

- **`VendingMachineModel`** содержит основную бизнес-логику и не зависит от визуального интерфейса Unity.
- **`VendingMachineStateMachine`** централизованно задаёт допустимые переходы между состояниями.
- **Контроллеры анимации** отображают события процесса; они не заменяют проверки бизнес-логики.
- **`PaymentController` и `RefundController`** отвечают за расчёты оплаты и контроль выполнения возврата.
- **`IngredientInventory`** проверяет и списывает ингредиенты по рецепту.
- **`SaveLoadService`** загружает настройки и обеспечивает запись сохранения с резервной копией.
- **`GameManager`** загружает данные и связывает модель, сцену, UI, звук и анимации.

Логика покупки построена так, чтобы повторные нажатия не приводили к повторному списанию ингредиентов или дублированию возврата и записи продажи.

## Состояния автомата

Основные состояния процесса покупки:

`Initial` → `WaitingForDrink` → `WaitingForPayment` → `CheckingPayment` → `PreparingDrink` → `ReturningChange` (если требуется) → `DispensingDrink` → `WaitingForPickup` → `Initial`.

При отмене или недостаточной оплате выполняется ветка возврата: `Refunding` → `Initial`. Также предусмотрены состояния ошибки и режима обслуживания.

Таймаут ожидания выбора по умолчанию составляет **60 секунд**, ожидания оплаты — **90 секунд**. Эти значения можно менять в конфигурации.

## Конфигурация и сохранения

**Начальные данные:**

`Assets/_Project/Resources/Config/default_data.json`

В этом файле задаются:

- номиналы принимаемых купюр;
- PIN персонала, громкость и состояние звука;
- таймауты;
- ингредиенты, количество, вместимость и минимальные остатки;
- список напитков, цены, рецептуры и время приготовления.

**Рабочее сохранение:** `cvm_save.json` в каталоге `Application.persistentDataPath`. Точный путь зависит от платформы; в редакторе его можно открыть через меню **CVM → Открыть папку сохранений**.

Начальная конфигурация применяется при первом запуске. Чтобы сбросить данные к исходным, закройте приложение и удалите `cvm_save.json`. При повреждённом сохранении приложение пытается использовать файл `.bak`, а если восстановление невозможно — загружает конфигурацию по умолчанию.

## Тестирование

### Через Unity Test Runner

1. Откройте проект в Unity Editor.
2. Выберите **Window → General → Test Runner**.
3. Перейдите в режим **EditMode** и запустите тесты.

Тесты находятся в `Assets/_Project/Tests/EditMode/VendingLogicTests.cs`.

### Через .NET CLI

Из корневой папки проекта выполните:

```bash
cd Tools/LogicTests
dotnet run
```

Консольный проект нацелен на **.NET 8** и запускает тесты бизнес-логики без Unity Editor. В наборе содержится 21 тест, охватывающий переходы состояний, оплату, возвраты, расход ингредиентов, таймауты и связанные сценарии.

### Ручная проверка интерфейса

Визуальные сценарии — запуск, адаптация окна, анимации, работа UI и сборка — следует дополнительно проверить в Unity Editor. Протокол ручной проверки находится в папке `Docs`.

## Сборка для Windows

1. Откройте проект в Unity Editor.
2. Убедитесь, что создана сцена `Assets/_Project/Scenes/Main.unity`.
3. В меню Unity выберите **CVM → Собрать Windows-приложение**.
4. При успешной сборке исполняемый файл будет создан по пути `Builds/CVM-2026/CVM-2026.exe`.

Также можно использовать стандартное окно **Build Settings** и выбрать **Windows, x86-64**.

## Известные ограничения

- Визуальное поведение необходимо подтвердить запуском в Unity Editor; расположение элементов и плавность анимаций проверяются вручную.
- Для проекта настроен Built-in Render Pipeline. Перенос на URP отдельно не подтверждён.
- Панель оплаты отображает до пяти номиналов — первые пять значений из конфигурации.
- Геометрия автомата и стакана создаётся программно и носит демонстрационный характер.
